# Role-to-Model Resolution in OMP Extensions

Learned the hard way debugging mprune and mmemory. Everything here is verified against live failures.

---

## The core problem

`ModelRegistry` has two distinct method sets. **Which registry object you have determines which methods are available.**

| Registry object | `getAll()` | `getAvailable()` | `getApiKey()` |
|---|---|---|---|
| `ctx.modelRegistry` (ExtensionContext) | ❌ undefined at runtime | ✅ works | ❌ authStorage crash |
| `runtime.ctx.modelRegistry` (slash command context) | ❌ same | ✅ works | ❌ same |
| `runtime.ctx.session.modelRegistry` (slash command only) | ✅ works | ✅ works | ✅ works |

`getAll()` and `getApiKey()` are only safe on the **session-level** registry (`runtime.ctx.session.modelRegistry`).  
The extension context registry (`ctx.modelRegistry`) only exposes `getAvailable()` and the canonical methods.

Calling `ctx.modelRegistry.getAll()` compiles fine (type says `ModelRegistry`) but returns `undefined` at runtime →  
`TypeError: undefined is not an object (evaluating 'registryN.getAll')`.

---

## Correct pattern: extension handler

```ts
// In api.on("turn_end", ...) or any ExtensionContext handler:
const registry = ctx.modelRegistry;

// Fallback chain: specific role → smol → default
const roleValue =
    settings.get("modelRoles.prune" as "modelRoles.smol") ??
    settings.get("modelRoles.smol") ??
    settings.get("modelRoles.default" as "modelRoles.smol");

const resolved = resolveModelRoleValue(roleValue, registry.getAvailable(), { modelRegistry: registry });
const model = resolved.model;
if (!model) {
    logger.warn("[ext] no model resolved");
    return null;
}

// DO NOT call registry.getApiKey() — completeSimple resolves the key internally
const response = await completeSimple(model, { systemPrompt, messages });
```

## Correct pattern: slash command handler (`/` commands in builtin-registry.ts)

```ts
// runtime.ctx.session.modelRegistry IS the full registry — getAll() works here
const registry = runtime.ctx.session.modelRegistry;

const roleValue =
    settings.get("modelRoles.prune" as "modelRoles.smol") ??
    settings.get("modelRoles.smol") ??
    settings.get("modelRoles.default" as "modelRoles.smol");

const resolved = resolveModelRoleValue(roleValue, registry.getAvailable(), { modelRegistry: registry });
const model = resolved.model;
if (!model) {
    runtime.ctx.showStatus("ext: no model configured.");
    return;
}

// completeSimple handles API key resolution internally
const response = await completeSimple(model, { systemPrompt, messages });
```

The helper `callLLMForMemory()` at the top of `builtin-registry.ts` follows this pattern — use it as a reference.

## What NOT to do

```ts
// ❌ getAll() — undefined on ExtensionContext registry
const resolved = resolveModelRoleValue(role, registry.getAll(), { modelRegistry: registry });

// ❌ getApiKey() — authStorage is null in extension context registry
const apiKey = await registry.getApiKey(model, sessionId);
const response = await completeSimple(model, { ... }, { apiKey });

// ❌ fallback to ctx.model — uses the active session model, not the role model;
//    its provider may have a different authStorage initialization state
const model = resolved.model ?? ctx.model;
```

## resolveModelRoleValue signature

```ts
resolveModelRoleValue(
    roleValue: string | undefined,    // e.g. "aws-corp/us.anthropic.claude-sonnet-4-6"
    availableModels: Model<Api>[],    // from registry.getAvailable() — NOT registry.getAll()
    options?: {
        settings?: Settings;
        matchPreferences?: ModelMatchPreferences;
        modelRegistry?: CanonicalModelRegistry;   // for canonical ID resolution only
    }
): ResolvedModelRoleValue
```

`CanonicalModelRegistry` is `Partial<Pick<ModelRegistry, "resolveCanonicalModel" | "getCanonicalVariants" | "getCanonicalId">>` — no `getAll`, no `getAvailable`, no `getApiKey`. Passing `ctx.modelRegistry` as `modelRegistry` option is fine — it has those three methods.

When `roleValue` is `undefined` or `"default"`, returns `{ model: undefined }` — handle it.

## ModelRegistry type hierarchy (model-resolver.ts:184)

```ts
export type CanonicalModelRegistry = Partial<Pick<ModelRegistry, "resolveCanonicalModel" | "getCanonicalVariants" | "getCanonicalId">>;
export type ModelLookupRegistry    = Pick<ModelRegistry, "getAvailable"> & Partial<CanonicalModelRegistry>;
type CliModelRegistry              = Pick<ModelRegistry, "getAll"> & Partial<CanonicalModelRegistry>;
type InitialModelRegistry          = Pick<ModelRegistry, "getAvailable" | "find">;
```

`CliModelRegistry` (requires `getAll`) is only used in `main.ts` startup — never in extension/slash-command code.

## completeSimple

`apiKey` is **optional**. `completeSimple` resolves the key internally via the model's provider.

```ts
// ✅ Correct — no explicit apiKey needed
const response = await completeSimple(model, { systemPrompt, messages });

// ✅ Also fine if you have a key
const response = await completeSimple(model, { systemPrompt, messages }, { apiKey });
```

Call shape confirmed from `builtin-registry.ts:135`:
```ts
completeSimple(model, { systemPrompt, messages }, { apiKey })
```

## sendMessage from slash commands

`api.sendMessage()` is only available inside extension factory closures (where `api: ExtensionAPI` is in scope).
Slash command handlers (`BuiltinSlashCommandRuntime`) do NOT have `api` — `runtime.ctx.sendMessage` does not exist.

To show output from a slash command flush, use `chatContainer` directly:

```ts
runtime.ctx.chatContainer.addChild(new Text(`mprune summary:\n${summary}`, 1, 0));
runtime.ctx.chatContainer.addChild(new Spacer(1));
runtime.ctx.ui.requestRender();
```
