## Phase 3 Items (implement in order — each unlocks the next)

### P3-1 — LLM extraction (simplified schema)
**Depends on:** Phase 2 complete (turn-boundary chunking must be validated first)  
**Unlocks:** P3-2 (consolidation), P3-3 (mental models), P3-4 (graph dedup)  
**Gap doc ref:** "Gap 3 — LLM extraction"

- [x] Wire `executePython` → `memory` role call in `retainSession()` when
      `extractionMode === "structured"`
- [x] Extraction prompt produces JSON array of `{fact, entities, date}` — three
      fields only; do NOT use 5-dim (what/when/where/who/why) schema (over-engineered
      for single-user local system; `who` = always user/assistant, `where` = always
      this project)
- [x] Write returned facts to `projectDir/facts.json` alongside the session `.md`
- [x] Add facts as a parallel retrieval path in `_handle_recall()`: embed facts,
      cosine-score separately, merge into RRF before chunk results (facts score
      higher than raw chunks — they are precision; chunks are breadth)
- [x] Keep verbatim `.md` files alongside extracted facts during transition;
      facts-only mode can be enabled in Phase 4 once extraction quality validated
- [x] Update `MmemoryConfig.extractionMode` comment: `structured` now active
- [x] Switch deployed configs from `extractionMode: verbatim` → `structured` after
      validating extraction quality against real session data
- [x] Embedding model upgrade: `BAAI/bge-base-en-v1.5` (768-dim, MTEB ~63.6) as
      a drop-in fastembed replacement — requires full rebuild of `index/`; do at
      the same time as extraction since rebuild is already required
### P3-2 — Consolidation
**Depends on:** P3-1 (needs `facts.json` populated)  
**Unlocks:** P3-3 (mental models need `observations.json`)  
**Gap doc ref:** "Gap 4 — Consolidation"

- [x] Add `/mmemory consolidate` command handler in `builtin-registry.ts`
- [x] Read `facts.json`; if below `maxRawFacts` threshold, return "nothing to
      consolidate yet" with threshold info
- [x] Call `executePython` → `memory.consolidate` role with consolidation prompt:
      pass N raw facts, ask to merge into M observations, deduplicate, flag
      superseded entries
- [x] Write `observations.json` to `projectDir/`
- [x] Add observations as highest-weight parallel path in `_handle_recall()`;
      observations rank above extracted facts which rank above raw chunks
- [x] Add `maxRawFacts` to `MmemoryConfig` (default: 100) — threshold that
      triggers automatic consolidation offer (not forced; show notice to user)
- [x] Update `consolidateModelRole` config comment: role is now active, operator
      should upgrade from `smol` to a model with large context window

### P3-3 — Mental models
**Depends on:** P3-2 (consolidation must produce `observations.json`)  
**Effort:** ~2 hours after P3-2  
**Gap doc ref:** "Gap 9 — Mental models"

- [x] After consolidation completes, run seed reflect pass for each built-in query:
      - `user-preferences` — "What does the user prefer in coding style, tooling,
        communication, and review? Capture only durable preferences."
      - `project-conventions` — "What are this project's conventions for code
        style, build, testing, release, and PR review?"
      - `project-decisions` — "What durable architectural or product decisions
        have been made, and what rationale was recorded?"
- [x] Each pass: `executePython` → `memory.consolidate` role, query over
      `observations.json`, write result to `projectDir/mental_models/<id>.md`
- [x] `mmemory-extension.ts` `session_start`: load all `mental_models/*.md`,
      concat into `<mental_models>` block, append to system prompt alongside
      recall snippet
- [x] Refresh: re-run seed passes at end of each `/mmemory consolidate` run —
      no TTL, no background timer, no delta mode (YAGNI)
- [x] Add `/mmemory mm list` command: list `mental_models/` files with last-modified

### P3-4 — Recall query composition
**Depends on:** Phase 2 complete (independent of extraction)  
**Gap doc ref:** "Recall query composition quality"

- [x] Replace `prompt.slice(0, 400)` in `mmemory-extension.ts`
      `before_agent_start` with multi-turn context composition:
      - Take last `recallContextTurns` user-bounded turns from session messages
      - Strip `<memories>` / `<mental_models>` tags (same regex as anti-feedback)
      - Suppress the latest user message from the context block (avoid duplication)
      - Truncate gracefully: preserve latest message, drop oldest context lines first
      - Budget: `recallMaxQueryChars` (add to `MmemoryConfig`, default 2000)
- [x] `recallContextTurns` already exists in `MmemoryConfig` (default 0 = disabled);
      flip default to 3 after this is implemented
- [x] Port Hindsight's `composeRecallQuery` / `truncateRecallQuery` logic from
      `src/hindsight/content.ts` — logic is clean and correct; adapt for TS

### P3-5 — Assistant message truncation removal
**Depends on:** Phase 2 complete (independent)  
**Gap doc ref:** "Assistant message truncation"

- [x] Remove `.slice(0, 1000)` cap on assistant messages in `buildTranscript()`
      in `mmemory-extension.ts`
- [x] If total transcript size is a concern, add `maxTranscriptChars` to
      `MmemoryConfig` (default: 0 = unlimited) — truncate oldest turns first,
      not individual responses

### P3-6 — Dual-system unification
**Depends on:** Phase 2 complete; natural refactor point before P3-1  
**Gap doc ref:** "The Dual-System Problem"

- [x] Extension owns ALL memory state; tools are thin dispatchers
- [x] `MmemoryRetainTool.execute()` → calls `ctx.getExtension("mmemory").retain(content)`
      rather than `executeMemoryRetain()` directly
- [x] `MmemoryRecallTool.execute()` → calls `ctx.getExtension("mmemory").recall(query, scope)`
- [x] `MmemoryReflectTool.execute()` → calls `ctx.getExtension("mmemory").reflect(query, scope)`
- [x] Extension exposes `retain(content, sessionId?)`, `recall(query, scope?)`,
      `reflect(query, scope?)` as a public API on the `ExtensionAPI` or via a
      shared session state accessor
- [x] Delete standalone `executeMemoryRetain` / `executeMemoryRecall` /
      `executeMemoryReflect` in `tools/mmemory/index.ts` — or keep as internal
      helpers called exclusively by the extension
- [x] Session dedup (Phase 2 item #5) becomes cleaner once tools access
      extension state: `sessionId` is no longer threaded as a parameter
