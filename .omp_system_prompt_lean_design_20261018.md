# OMP System Prompt — Lean/Improve Design (informed by DeepSeek Harness comparison)

Date: 2026-10-18. Status: DESIGN, not implemented. Author: agent session. Companion to `.omp_deep_seek_web_design_20261018.md`.
Purpose: concrete plan to slim and modernize OMP's system prompt, with a per-model-class `prompt-style` mechanism so OMP renders lean for strong models (notably DeepSeek) while keeping full guardrails for weak ones. Every current-state claim carries file:line; implementer re-validates anchors before editing (upstream restructures move lines).

---

## 0. TL;DR

- Keep the delivery contract (`<contract>/<completeness>/<evidence>/<yielding>`) untouched — it is the one block DeepSeek lacks and the one that catches real failures.
- Shrink the rest: kill the RFC 2119 preamble, cut ~37 NEVER/MUST NOT to ~10 load-bearing, compress the 6-phase Workflow to ~4 lines, collapse the Visuals and Delegation conditional blocks, dedupe injected generic-rules against the base at assembly time.
- Add a catalog axis `prompt-style: full|lean` (mirrors the existing `web-search` axis) — DeepSeek class (and opt-in frontier classes) render lean; weak/unknown classes keep full.
- Adopt three DeepSeek mechanisms: per-tool guidance colocated in tool packages (scope-aware, auto-dropping), dynamic policy facts as user-role history snapshots instead of system-template conditionals, loud assembly failures on unresolved template variables.
- Guardrail: no mass-trim without A/B eval on the models that actually run through OMP; DeepSeek's sparse style is valid only for models trained for it.

- Identity: 9 words, order −1000 (`packages/core/system-prompt/README.md:144-146`).

- Output-boundary obligations only: deliverable file references (9000), structured_output (9900); generated per-composition `tools:sdk` (5000) (`packages/core/tools/README.md:182`).
- Philosophy: facts + obligations, near-zero prohibitions, model trusted — valid because DeepSeek owns model training end-to-end. Hand-written system text <1K tokens.

## 2. Remove / shrink (ordered by expected benefit)

1. **RFC 2119 preamble (system-prompt.md:1-2) → delete or collapse to one line** ("MUST/NEVER = hard requirements"). Rationale: metalanguage sets a legalistic register and burns prefix tokens every request; DSH has zero.
2. **NEVER/MUST NOT count 37 → ~10.** Keep: anti-fabrication, no unfinished work/stubs, no silent scope shrink, evidence-only reporting, sed/perl-edit ban (:119-123), destructive-command guard (:203), verify-by-running (:212). Demote to SHOULD or delete: stylistic Visuals NEVERs (:13-27), "never re-audit applied edit" (:263), "never open guessed files" (:134, covered by find-first :114), budget-narration ban (:262), emoji/visual rules. Negative pressure buys nothing from frontier models and taxes weak ones' instruction budget.
3. **Workflow § (:182-233) → ~4 lines.** Keep: plan multi-file work before opening files; read relevant sections first; verify by running the changed path; cleanup scaffolds. Move to dedicated surfaces: todo init/done pairing detail (→ todo tool description), subagent hand-off variant (:205-209, → task-agent prompt), UI/TUI verification sub-bullets (→ browser/computer tool docs), test-writing policy (:225-229, → a skill or eval guidance). Strong models plan without scaffolding; weak models still get the verify core.
4. **Visuals conditional block (:12-28, ~17 lines) → 1 line + capability-gated detail.** Keep "prefer table/chart/diagram over prose; use the rendered forms your tools expose"; move viewBox/color-palette rules into the svg-render tool schema or a skill.
5. **Delegation § (:147-180) → policy one-liner + gates.** Collapse the `delegationBias` × `eagerTasks` × `inlineFirst` combinatorics (worst cache-hostile region of the template) into the policy line rendered from settings; keep the Delegation gates list (:172-179) — those catch real subagent-storming failures.
6. **Dedupe injected rules at assembly time.** `generic-rules` frequently duplicate Tool Policy (observed: git-grep mandate vs specialized-tool routing). In `system-prompt.ts` assembly, drop an injected rule whose normalized text overlaps a base rule's anchor verbs; log the drop. Do not touch user files.

## 3. Add

1. **Catalog axis `prompt-style: full|lean`** — the mechanism that makes OMP render lean for DeepSeek (and opt-in frontier classes) without touching weak-model behavior. Design in §4.
2. **Per-tool guidance colocation (DSH pattern).** Each tool package exports one scope-aware guidance string (exported const or `defineTool({ guidance })`); `system-prompt.ts` renders it under # Tool Policy only when the tool is present. Kills central-template drift, shrinks the base, matches DSH `tool:edit`/`tool:bash` evidence. Migration: move existing per-tool bullets from system-prompt.md (:106-118, :136-145) into their tool packages verbatim first, trim later.
3. **Dynamic policy facts → user-role history snapshots (DSH pattern).** Delegation bias, approval policy, environment deltas render as sourced context entries in history instead of system-template conditionals; system prefix becomes composition-stable → KV reuse. OMP already has the machinery (steering/context injection, `ttsr`); this reuses it.
4. **Loud assembly failures (DSH pattern).** Unresolved `{{variable}}`/unknown section in system-prompt.md → throw at rebuild with the variable name, not silent empty rendering. Silent drops hid stale templates; DSH treats malformed prompts as worse than failures.
5. **Capability-aware Tool Policy render.** For models whose catalog `identity` marks frontier classes, render the specialized-vs-shell routing block (:105-118) compressed (one line per rule); weak classes keep full. Same mechanism as §4 (class rules in KDL).

## 4. `prompt-style` axis — exact mechanism

1. `packages/catalog/src/compat/axes.ts`: add `"prompt-style": { key: "promptStyle", set: "catalog", shape: "scalar", values: ["full", "lean"] }` (sibling of `"web-search"` at :433-438).
2. `packages/catalog/src/build.ts` `applyCatalogAssignments` (:57-68): `if (catalog.promptStyle === "lean" || catalog.promptStyle === "full") model.promptStyle = catalog.promptStyle;` + `Model.promptStyle?: "full" | "lean"` in `packages/catalog/src/types.ts` (near `webSearch` :1497-1500).
3. Class rule (KDL, e.g. new `compat/rules/classes/deepseek.kdl` or provider rule): `class "deepseek" { prompt-style "lean" }` — same rule shape as existing class rules; regen via `bun run gen:compat` (`compat/rules/README.md:21`). Opt-in for other classes stays explicit — nothing flips silently.
4. Render: `system-prompt.ts` reads the resolved model's `promptStyle` (default `"full"` when unset) and feeds it as a template flag; system-prompt.md gains `{{#if lean}}` gates around: RFC preamble (dropped in lean), Workflow (4-line variant), Visuals block (1-line variant), Tool Policy compressed variant. The delivery contract blocks (:236-257) render in BOTH styles unchanged.
5. Fallback: unknown/uncataloged models → `full` (today's behavior, zero regression surface).

## 5. What stays untouched

- `<contract>/<completeness>/<evidence-and-output>/<yielding>` (:236-257) — render verbatim in both styles. This is the anti-fabrication core DSH lacks.
- Delegation gates (:172-179).
- The specialized-tool sed/perl ban (:119-123) and destructive-command guard (:203).
- Tool inventory / internal URLs / xd devices sections — they are facts, not rules.

## 6. Verification plan (A/B before any mass-trim lands)

1. Unit: snapshot tests for both render styles (`system-prompt-inventory.test.ts` pattern); loud-failure test for unresolved variables.
2. A/B harness: same task battery through `full` vs `lean` (and vs current baseline) on (a) a DeepSeek V4-class model, (b) one mid-tier model (must not regress), (c) one weak/open model (must not regress). Metrics: task success via judge, tool-misuse rate (bash-for-edit attempts), fabrication incidents, token spend, cache hit rate (system prefix stability).
3. Rollout: axis defaults to unset (= full) for every class except `deepseek`; flip other classes only with eval evidence.
4. Bench fixtures exist for prompt work: `prompts/bench/cache-prefix*.md`, `prompts/bench/chat.md` — extend rather than invent new harnesses.

## 7. Risks

- Lean render on a model class that actually needed the guardrails → silent quality regression; mitigated by (b)/(c) regression gates in §6.
- Colocating tool guidance touches every tool package — mechanical but wide; do it verbatim-first (§3.2), trim in a second pass.
- The dedupe pass (§2.6) risks dropping rules with subtle conditions; keep it log-only (report, don't drop) in v1.
- Upstream divergence: upstream may modernize its own prompt; re-validate anchors after each sync (same discipline as the deepseek dossier §6.0).
