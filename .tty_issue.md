# Bug: `omp -c` crashes with exit code 129 when run from Git Bash / MSYS2 terminal

**Reproduced on:** Windows 11, OMP v17.2.12, Git Bash (MSYS2)
**Regression introduced by:** Commit `72d8d4eaca` — "fix(cli): restored piped session persistence" (Aug 2, 2026)

## Summary

Running `omp -c` from Git Bash exits silently with return code 129. The same command works fine from native Windows Terminal, cmd.exe, and PowerShell (exit 0). No output, no error message -- just exit 129.

Exit code 129 originates from Bun's crash handler via `postmortem.quit(129)` after an uncaught exception in the TUI initialization path triggered by the new stdin detection logic.

## Steps to Reproduce

1. Open Git Bash on Windows (MSYS2 shell where `stdin.isTTY` reports as a TTY stream object, not boolean `true`)
2. Navigate to any project directory with existing sessions
3. Run `omp -c`

**Expected:** OMP enters interactive mode, loads the most recent session, shows the session transcript.

**Actual:** Process exits immediately with return code 129. Stdout captures exactly 93 bytes of ANSI escape sequences (terminal cleanup sequences), stderr is empty.

No other modes are affected (`-p`, `-r`, normal interactive launch without `-c` all work).

## Root Cause

In commit `72d8d4eaca`, `readPipedInput()` was changed from:

```typescript
// Before (correct):
if (process.stdin.isTTY !== false) return undefined;
```

to:

```typescript
// After (regression):
if (process.stdin.isTTY === true) return undefined;
```

The loose check `!== false` treats any truthy value (boolean `true` or a TTY stream object) as a real terminal -- returns undefined early -- `autoPrint = false` -- `isInteractive = true`.

The strict check `=== true` only matches the literal boolean `true`. On MSYS2/Git Bash, `process.stdin.isTTY` is a **TTY object** (truthy, but not the literal `true`), so the condition fails. The code proceeds to call `Bun.stdin.text()`, which attempts to read from the PTY rather than recognizing it as an interactive terminal. This causes the TUI's `ProcessTerminal.start()` to call `setRawMode(true)` on the MSYS2 PTY layer, which throws. The exception propagates through `#markTerminalDisconnected()` -- `disconnectHandler()` fires -- `postmortem.quit(129)`.

### Environment-specific behavior

| Shell | `process.stdin.isTTY` | `isTTY === true` | `isTTY !== false` | Result |
|---|---|---|---|---|
| Windows Terminal / cmd.exe | `true` (boolean) | match | match | Works (both paths correct) |
| PowerShell | `true` (boolean) | match | match | Works (both paths correct) |
| Git Bash / MSYS2 | TTY stream object | no match | match | Crash (only old code worked) |
| Piped input / `$ echo "" \| omp` | `false` (boolean) | skip (not true) | skip (is false) | Works (both paths correct) |
| Subprocess / Python `subprocess.run` | `false` or undefined | depends | depends | Variable |

The regression specifically breaks anything running OMP under a PTY-based non-Windows-console shell on Windows (Git Bash, MSYS2, WSL bash via proxy, etc.).

## Fix

Revert line ~195 in `packages/coding-agent/src/main.ts`:

```diff
/** Reads a non-TTY stdin stream as prompt text. */
export async function readPipedInput(): Promise<string | undefined> {
-   if (process.stdin.isTTY === true) return undefined;
+   if (process.stdin.isTTY !== false) return undefined;
}
```

The original `!== false` contract is correct: "if isTTY is truthy (boolean true OR a TTY object), this is a real terminal -- skip piped-input logic." Only `false` means definitely not a terminal.

An alternative that is more explicit about intent:

```typescript
if (process.stdin.isTTY == null) return undefined;
```

This only falls through when the value is genuinely unknown/null, covering both `false` (definitely piped) and `true`/TTY objects (definitely a terminal). However, `!== false` is the safer, battle-tested original that preserves the "truthy means terminal" semantic.

## Verification

After applying the fix, `omp -c` now exits with code 0 and launches interactive mode normally from Git Bash. Tested with compiled binary deployed via `install-open-sdk.py --skip-natives`.
