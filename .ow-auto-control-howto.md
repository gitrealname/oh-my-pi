# ow automated testing — agent guide

How to test OMP (`ow`) changes programmatically. Two modes exist; choose based on what needs testing:

| Need | Tool | Why |
|---|---|---|
| Session lifecycle, mmemory, model calls, tool output | `-p` flag (§1–7) | Headless, fast, scriptable from bash |
| ESC cancellation, TUI navigation, keypress behaviour, slash commands, any UI interaction | `mtuicontrol` (§10) | Requires a live headed TUI; `-p` silently passes these |

**Key constraint:** `mcommand` (the LLM tool that drives mtuicontrol) only fires when called from an **interactive `o --new` or `ow --new` session**. It does nothing in `-p`/headless mode — there is no `SCHEDULE_SLASH_CHANNEL` listener. Always load the `mtuicontrol` skill and ensure `mtuicontrol: enabled: true` is in config before testing.

---

## 1. The `-p` flag (non-interactive / print mode)

```bash
"$LOCALAPPDATA/omp/omp.exe" -p "your message here" --no-lsp --no-pty --model "openrouter/xiaomi/mimo-v2-flash"
```

`-p` runs a complete session and exits without a TTY. The full lifecycle fires in order:

```
session_start
  → beforeAgentStartPrompt   (mmemory injects stored context here)
  → buildDeveloperInstructions
  → agent turn (model sees the injected context)
  → agent_end / retain       (new chunks written back to store)
```

No interactive terminal is required. stdout and stderr are merged; pipe or redirect freely.

---

## 2. Which model to use

**Always use:** `openrouter/xiaomi/mimo-v2-flash`

- Cheap, fast, no Windows auth required from a headless bash context.
- Suitable for lifecycle validation — the model content does not matter, only that the session runs end-to-end.

**Never use from headless bash:** `aws-corp/...` (Bedrock) models. These require Windows integrated authentication that is not available in a non-interactive shell. The session will hang or error at auth.

## 4. Killing a stale mmemory server

The mmemory server (port 49200) is auto-started by the first ow session and reused. If it is stale or holding bad state, kill it — the next ow session restarts it from the deployed binary's bundled Python source.

```bash
# Find the PID listening on port 49200
netstat -ano | grep 49200

# Kill it (replace N with actual PID from above)
taskkill /PID N /F
```

The server auto-restarts on the next `ow -p` invocation. No manual start is needed.

## 5. Checking injection evidence in logs

Log file (rolling daily):
```
D:/.ai/.junctions/omp/logs/omp.2026-05-09.log
```

Key patterns to grep for after a headless run:

```bash
# Injection at beforeAgentStartPrompt — confirms mmemory loaded context
grep "\[mmemory-backend\] beforeAgentStartPrompt" D:/.ai/.junctions/omp/logs/omp.2026-05-09.log | tail -5
# Expected: sessions=N obs=M files=K snippetLen=L   (snippetLen > 0 = injection active)

# Injection forwarded to developer instructions
grep "buildDeveloperInstructions" D:/.ai/.junctions/omp/logs/omp.2026-05-09.log | tail -5
# Expected: snippetLen=L (same value)
```

A `snippetLen=0` means no prior context to inject (fresh DB or no matching chunks). Anything above 0 confirms the pipeline is live.

## 6. Querying the server directly

The mmemory server uses newline-framed JSON over TCP. Use Python to call `get_injection_snapshot`:

```python
import socket, json

def query_server(port=49200, project="--D--.ai--"):
    req = json.dumps({"method": "get_injection_snapshot", "params": {"project": project}}) + "\n"
    with socket.create_connection(("127.0.0.1", port), timeout=5) as s:
        s.sendall(req.encode())
        buf = b""
        while b"\n" not in buf:
            chunk = s.recv(4096)
            if not chunk:
                break
            buf += chunk
    return json.loads(buf.split(b"\n")[0])

result = query_server()
print(json.dumps(result, indent=2))
```

See `packages/coding-agent/src/tools/mmemory/test_injection_snapshot.py` for the full reference implementation.

The response contains `sessions`, `observations`, `files`, and `snippet` fields — same data logged at `beforeAgentStartPrompt`.

## 7. Full end-to-end verification flow

Runnable bash block. Records log position before the run, fires one ow session, extracts `snippetLen` from the delta, asserts it is non-zero.

```bash
#!/usr/bin/env bash
set -euo pipefail

LOG="D:/.ai/.junctions/omp/logs/omp.2026-05-09.log"
OW="$LOCALAPPDATA/omp/omp.exe"
MODEL="openrouter/xiaomi/mimo-v2-flash"
CWD="D:/.ai"

# Snapshot log size before run
BEFORE=$(wc -l < "$LOG" 2>/dev/null || echo 0)

echo "Running headless ow session..."
"$OW" -p "ping — mmemory lifecycle check" --no-lsp --no-pty --model "$MODEL" 2>&1

# Extract injection log lines added during this run
AFTER=$(wc -l < "$LOG")
DELTA=$(tail -n $(( AFTER - BEFORE )) "$LOG")

echo "--- log delta ---"
echo "$DELTA" | grep -E "mmemory-backend|buildDeveloperInstructions" || true

# Extract snippetLen value
SNIPPET_LEN=$(echo "$DELTA" | grep -oP "snippetLen=\K[0-9]+" | head -1 || echo "")

if [[ -z "$SNIPPET_LEN" ]]; then
  echo "WARN: snippetLen not found in log delta — mmemory may not have injected"
elif [[ "$SNIPPET_LEN" -gt 0 ]]; then
  echo "OK: snippetLen=$SNIPPET_LEN (injection active)"
else
  echo "WARN: snippetLen=0 (no prior context — expected on fresh DB)"
fi
```

Run this from any shell where `$LOCALAPPDATA` resolves (Windows bash/MSYS2/Git Bash). The `cwd` used by `ow` is inferred from the working directory of the process — since `ow` is called with an absolute path, ensure the shell's `$PWD` is `D:/.ai` or pass an explicit `--cwd` if the binary supports it. Safest: `cd "D:/.ai"` before the ow call when not using `set -euo pipefail` constraints.

## 10. Programmatic TUI control — mtuicontrol

Use when you need to test **interactive / headed** behaviour that `-p` cannot reach:
ESC cancellation mid-task, TUI navigation (`/mtree`, `/help`), slash command injection,
or any scenario that requires a live terminal UI.

### Prerequisites
```yaml
# ~/.omp/agent/config.yml  or  .omp-work/agent/config.yml
mtuicontrol:
  enabled: true   # default: false
```
Skill file must be loaded: `skill://mtuicontrol` (auto-loaded when enabled).

### How it works
```
LLM agent (master session)
  └─ mcommand({ command: "/mtuicontrol spawn --cmd ..." })
       └─ SCHEDULE_SLASH_CHANNEL → /mtuicontrol handler
            └─ RpcPipeClient.start() → createPipeServer() (TCP, Windows)
                 └─ spawns child: cmd.exe /c start "" ow --new --no-memory --rpc-pipe PORT
                      └─ child connects back → JSONL over TCP side-channel
                           └─ master controls child: prompt / keypress / command / stop
```

### Commands
| Command | Effect |
|---|---|
| `spawn --cmd "cmd.exe /c ow --new --no-memory"` | Open headed child TUI; returns session id + child pid |
| `prompt [id] [--timeout N] <message>` | Send prompt, wait for full response (synchronous) |
| `keypress [id] <ESC><CTRL-C><DOWN>...` | Inject real keypresses through full TUI pipeline |
| `command [id] /changelog full` | Execute slash command at TUI layer (LLM never sees it) |
| `stop [id]` | Terminate child session |
| `list` | Show active session ids |

### When to use mtuicontrol vs -p
| Scenario | Use |
|---|---|
| mmemory lifecycle, injection, consolidation | `-p` (headless, fast) |
| ESC cancellation mid-task | mtuicontrol (requires live TUI) |
| TUI navigation (`/mtree`, `/help`, panels) | mtuicontrol |
| Slash command execution testing | mtuicontrol |
| Startup / model / provider validation | `-p` |

### ESC regression test (core — run after every parallel.ts change)
```javascript
// In o --new session (master):
mcommand({ command: '/mtuicontrol spawn --cmd "cmd.exe /c ow --new --no-memory"' })
// → "Session rpc-<id> ready. (child pid=XXXX)"

mcommand({ command: "/mtuicontrol prompt --timeout 15000 use the task tool with quick_task agent to run bash: sleep 30, then say DONE" })
// → "Child (aborted by ESC): ..."  must arrive in <3s after ESC fires at 15s
// → FAIL if session terminated (means parallel.ts abort race not fixed)

mcommand({ command: "/mtuicontrol stop" })
```

### Notes
- `--no-memory` disables mmemory on the child — keeps tests fast and credential-safe.
- `cmd.exe /c start "" ow ...` opens a visible window (good for debugging).
  Omit `start ""` for headless pipe-only operation (window not visible).
- On credential expiry (~50s), the child's second LLM call fails with
  `TypeError: result.usage`. Non-fatal — task still aborts correctly on ESC.
- Log: `C:/Users/common/.omp/logs/omp.YYYY-MM-DD.log` — filter `[mtuicontrol]`,
  `[rpc-inject]`, `[pipe-transport]` for pipe transport tracing.
